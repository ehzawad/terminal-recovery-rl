# TerminalWorld

## Dataset Summary

TerminalWorld is a benchmark dataset for evaluating AI agents on real-world terminal and command-line tasks. It contains 1,530 terminal-based tasks reverse-engineered from publicly available terminal recordings, covering domains such as data processing, system administration, networking, security, version control, containers and orchestration, debugging and testing, environment setup, and scientific computing.

Each task includes a natural language instruction, an oracle solution, state-based evaluation tests, and a reproducible Docker execution environment. The dataset is designed to measure how reliably AI agents can understand terminal workflows, execute shell commands, reproduce correct environment states, and pass automated verification tests.

This is the official dataset for the paper **TerminalWorld: Benchmarking Agents on Real-World Terminal Tasks**.

## Dataset Variants

The dataset is organized into three configs:

| Config | Tasks | Description |
|--------|-------|-------------|
| `full` | 1,530 | All TerminalWorld tasks generated by the data pipeline. |
| `verified` | 200 | A curated subset of `full` that has passed manual human verification, including review of instruction clarity, artifact completeness, oracle replayability, and state-test validity. |
| `sample` | 20 | A small random sample from `verified` for quick inspection and development. |

## Intended Use

TerminalWorld is intended for:

- Evaluating terminal and coding agents in reproducible local environments.
- Measuring CLI reliability, environment reproduction, oracle-solution replay, and state-based task evaluation.
- Comparing agent architectures on real-world terminal workflows.
- Academic research on AI agents for software engineering and system administration.

The `verified` subset is recommended as the primary evaluation subset for benchmarking.

## Out-of-Scope Use

TerminalWorld is NOT intended for:

- Training general-purpose autonomous agents for unrestricted real-world system operation.
- Security-sensitive command execution or credentialed cloud administration.
- Evaluating GUI/TUI-heavy operations or workflows requiring authenticated credentials.
- Measuring general software engineering ability in all developer contexts.

## Data Format

Each task is stored as a JSONL record with the following fields:

| Field | Type | Description |
|-------|------|-------------|
| `task_id` | string | Unique task identifier (e.g., `"tw_100135"`) |
| `instruction` | string | Natural language task description |
| `artifact_path` | string | Relative path to the compressed task artifact |
| `requires_docker` | boolean | Whether the task requires Docker |
| `terminal_domain` | string | Task category (e.g., Data Analysis, Version Control, Security) |
| `source_type` | string | Origin of the source material |
| `pii_status` | string | PII handling status |
| `license` | string | Dataset license |

## Artifact Format

Each task artifact (`artifacts/{task_id}.tar.gz`) contains the following structure:

```
{task_id}/
├── task.toml           # Task metadata and configuration
├── instruction.md      # Natural language instruction
├── solution/           # Oracle solution scripts
├── tests/              # State-based evaluation tests
└── environment/        # Docker build context (Dockerfile, assets)
```

To download and unpack a specific artifact:

```python
from huggingface_hub import hf_hub_download
import tarfile

# Download
path = hf_hub_download(
    repo_id="EuniAI/TerminalWorld",
    filename="artifacts/tw_100135.tar.gz",
    repo_type="dataset",
)

# Unpack
with tarfile.open(path, "r:gz") as tar:
    tar.extractall(path="./my_tasks")
```

Alternatively, use the provided scripts:

```bash
python scripts/download_artifacts.py --task-id tw_100135
python scripts/unpack_task.py --archive downloaded_tasks/artifacts/tw_100135.tar.gz
```

## Human Verification / Verified Protocol

The `verified` subset contains 200 tasks that have been manually reviewed by human annotators. The verification protocol includes:

1. **Instruction clarity**: The task instruction is unambiguous and correctly describes the expected behavior.
2. **Artifact completeness**: All required files (task.toml, instruction.md, solution/, tests/, environment/) are present and valid.
3. **Oracle replayability**: The oracle solution executes successfully in the provided Docker environment and produces the expected output.
4. **State-test validity**: The automated state tests correctly distinguish between successful and failed task completion.

## Data Collection and Processing Pipeline

TerminalWorld is generated by a multi-stage data engine:

1. **Public terminal recording collection**: Terminal session recordings are collected from publicly available sources.
2. **Preprocessing and filtering**: Recordings are cleaned, deduplicated, and filtered for suitability.
3. **Task intent inference**: The intended task and goal are inferred from each recording.
4. **Oracle solution extraction**: Successful command sequences are extracted as oracle solutions.
5. **Execution environment reproduction**: Docker environments are constructed to reproduce the original execution context.
6. **State-test generation**: Automated tests are generated to verify task completion.
7. **Task refinement**: Tasks are iteratively refined for clarity, reproducibility, and evaluation quality.
8. **Human verification** (for the `verified` subset): Tasks are manually reviewed against the verification protocol.

## Privacy and Sensitive Information Mitigation

The dataset construction pipeline includes filtering and sanitization steps to remove personally identifiable information, credentials, tokens, private paths, emails, usernames, hostnames, API keys, and other sensitive strings where detected. The released task artifacts are designed not to contain raw terminal recordings or personally identifying account-level metadata. However, because the source material originates from public human terminal operations, residual sensitive information risk cannot be completely eliminated.

## Limitations and Biases

TerminalWorld focuses on terminal-based tasks reverse-engineered from publicly available terminal recordings. It may underrepresent:

- Workflows that are not commonly shared publicly.
- Tasks involving private enterprise infrastructure.
- GUI/TUI-heavy operations.
- Long-running cloud deployments.
- Workflows requiring authenticated credentials.

The dataset inherits selection bias from public terminal recording platforms. Users who publish terminal recordings may differ from the broader developer population in expertise, tooling preferences, operating systems, language ecosystems, and willingness to share workflows publicly.
