The most urgent are the verifier’s shared-process trust boundary, skipped tests receiving pass credit, infrastructure errors retaining successful scores, incomplete contracts, and headline episodes reusing selection seeds.

**Priority before selection and gates:** repair verifier authentication/completion accounting; make error outcomes consistently zero-credit and denominator-preserving; resolve contract gaps affecting admitted tasks; freeze the validity/contracts and row identities; make headline seeds fresh; and ensure every possible P controller can be used by the variance gate and training. The sandbox parsing defects below are smaller but should also be corrected before freezing this harness.

**Work that can wait until before training:** durable attempt/time accounting and restart handling; effective-gradient liveness; completion-length and truncation recording; S/D empty-data and deadline handling; an executable checkpoint-selection procedure; stronger final-analysis identity checks; and the required long-trajectory memory and nonzero adapter-sync demonstrations. The following are the most material new or remaining defects.

**V1 — The nonce does not authenticate results against code imported into pytest.** The runner stores `nonce` and `c` in its module globals, then invokes pytest in that same interpreter: [verify.py:30](/mnt/sdb/arafat/ehz/llm/terminal-recovery-rl/termrl/verify.py:30), [verify.py:48](/mnt/sdb/arafat/ehz/llm/terminal-recovery-rl/termrl/verify.py:48). Imported task code can access `__main__.nonce` and modify `__main__.c.res`. Closing stdin does not create an isolation boundary inside one interpreter.

This is relevant to an admitted task: the ETL tests import the agent-edited `transform.py` directly at [test_final_state.py:51](/mnt/sdb/arafat/ehz/llm/.pools/endless-terminals/task_000000_8cd60f14/tests/test_final_state.py:51), and its v4 contract is present at [contracts_v4.jsonl:49](/mnt/sdb/arafat/ehz/llm/terminal-recovery-rl/data/contracts_v4.jsonl:49). My in-memory execution of the actual runner, with a simulated imported artifact, read the nonce and replaced the collector’s results. This was a unit reproduction, not a container exploit. The reported subprocess nonce-abuse test does not cover this case.

The minimal safe architectural change is to execute submitted Python in a worker separated from the trusted test/controller process, with no access to its memory or result channel. Alternatively, exclude tasks requiring in-process imports until that separation exists. Moving the nonce into a closure is insufficient.

**V2 — Skipped or unexecuted tests can count as passed; abnormal exits remain accepted.** `Collect` starts every reported node at `ok=True` and only marks skips unsuccessful when `report.when == "call"`: [verify.py:39](/mnt/sdb/arafat/ehz/llm/terminal-recovery-rl/termrl/verify.py:39). Ordinary `skipif` skips occur during setup. A setup-skipped node plus teardown therefore satisfies the inventory and counts as passed without a call-phase execution.

Another admitted test has an agent-creatable skip-marker condition at [test_final_state.py:150](/mnt/sdb/arafat/ehz/llm/.pools/endless-terminals/task_000000_1b89c6f9/tests/test_final_state.py:150).

Require explicit successful call-phase completion for pass credit, record all phases, validate the report schema and exit statuses, and reject incomplete/internal-error runs. If permanently optional tests are excluded, record that exclusion prospectively in the trusted inventory rather than treating skips as passes. Revalidate affected inventories and rewards.
